# 手机自动寻找已配对电脑

日期：2026-10-04
状态：待用户核对具体设计；尚未修改产品代码或网络设置。

## 已确认的目标

手机继续直接连接现有校园 Wi-Fi。用户没有校园网或运营商的 DHCP 管理权限，也不接受改连电脑热点。用户已选择固定配对名称、自动寻找已配对电脑，并同意修改电脑端和安卓伴侣。

本方案固定的是电脑的配对身份和显示名称。校园网分配的数字 IP 仍可能变化；在网络允许局域网服务发现时，手机自动更新连接地址。首次配置令牌后，用户不必因为 IP 变化反复手动填地址。

## 使用方式

1. 电脑运行 start-lan.cmd，网页“手机连接”显示固定的配对名称以及自动发现状态。
2. 用户覆盖安装新版 CourseInbox 伴侣，沿用原应用签名和包名，保留配置与待传队列。
3. 手机填写一次电脑访问令牌，点击“自动寻找并配对电脑”。也支持先用已知地址完成首次配对。
4. 手机确认电脑持有相同配对令牌后，保存其固定身份和名称。之后优先验证上次地址；地址失效时在当前 Wi-Fi 寻找同一台电脑，验证成功后保存新地址并补传。
5. 新消息进入原有收件箱和任务草稿确认流程。
6. 电脑离线、发现被网络阻断或身份验证失败时，事件保留在队列，界面显示原因。用户可查看电脑网页最新地址并使用手动地址入口。

校园 Wi-Fi 对广播或多播的支持需要在用户手机上实测。如果网络阻断发现，本方案不能承诺每次 IP 变化都自动恢复；此时需要手动地址或校园网管理员提供地址保留。

## 电脑身份与发现信息

在 data/mobile-device.json 保存随机生成的 128 位电脑身份。名称采用 CourseInbox 加身份的短前缀。该身份随 data 备份恢复，不随 IP 变化。

电脑只在局域网监听模式发布 DNS-SD 服务 _courseinbox._tcp.local.，记录当前私有 IPv4 和实际 HTTP 端口。发现信息只包含协议版本、电脑身份与名称，不包含令牌、班级、课程或通知内容。

使用 python-zeroconf；依赖安装在项目自己的 Python 环境中，不修改全局 Python。缺少依赖时显示自动发现不可用，并保持手动连接可用。普通仅本机启动模式不发布发现服务。

服务运行时每 2 秒检查本机 IPv4。地址改变时更新发现记录，同时刷新 HTTP Host 校验使用的本机地址集合。关闭服务器时注销发现信息并停止后台线程。自动发现只接受 RFC 1918 私有 IPv4，不使用代理虚拟网卡的测试地址。

## 配对验证协议

新增只读 GET /api/mobile/pairing?challenge=<nonce>。nonce 为 32 个随机字节的小写十六进制表示。接口返回：

- version：固定为 1。
- device_id：固定电脑身份。
- name：固定显示名称。
- challenge：原样返回本次 nonce。
- address：经过 Host 校验的请求目标 IPv4。
- port：服务器实际端口。
- proof：HMAC-SHA256 的小写十六进制结果。

HMAC 使用现有访问令牌作为密钥。输入为 UTF-8 编码的五行文本：
courseinbox-pair-v1、device_id、challenge、address、十进制 port，行之间用 LF 分隔，末尾不加换行。

手机发起验证请求时不发送访问令牌。手机根据自己的令牌独立计算 proof，并同时检查 challenge、目标地址、端口和已保存的 device_id。全部相符后，才向该地址发送带令牌的通知请求。身份不匹配的其他电脑不会替换已配对电脑。

令牌改变时需显式重新配对。发现记录不作为可信依据；校园网现有 HTTP 连接仍适用于用户认可的局域网使用范围。

## 手机行为

新增独立的 ComputerDiscovery 类处理 Android NsdManager 服务发现，新增 PairingProof 类处理纯 Java 验证逻辑。

手机保存 device_id、固定名称和最近一次验证成功的地址。初次自动寻找只接受能通过当前令牌验证的服务；已有配对时只接受同一身份。需要更换电脑时提供明确的重新配对操作。

发现和验证在后台执行，界面显示“寻找电脑”“已配对”或明确失败原因。单次发现设置有限超时，释放发现监听器；找到候选但验证失败时继续检查其他候选。不会因为发现失败移除队列事件。

沿用打开客户端、通知监听连接、新通知到来和手动重试的补传触发方式，不承诺手机休眠时持续寻找。上传收到 HTTP 200 或 201 后才移除事件，原通知标识和时间用于去重。

界面保留手动地址、令牌、班级与应用白名单。请求只使用验证过的私有 IPv4；发现后的实际地址可查看。必要的网络状态权限在 AndroidManifest.xml 声明，不引入 Wi-Fi Direct、热点或外部账号。

## 启动与防火墙

start-lan.cmd 保持现有启动入口。首次安装发现依赖和配置防火墙需要一次 Windows 管理员确认，完成后不因普通 DHCP 地址变化再次修改规则。

更新现有 CourseInbox TCP 8765 规则：绑定实际服务 Python 程序和 WLAN 接口，本地地址限制为 RFC 1918 IPv4 范围，远程地址为当前 LocalSubnet。规则适用于公用和专用网络。

为同一程序及 WLAN 接口配置 UDP 5353 发现规则，远程范围为 LocalSubnet。不开启其他应用、端口或公网访问。

同机验证发现记录能被找到、验证接口能被正确校验。交付新版 APK、启动入口和验证记录，清楚区分电脑验证与手机实测。
