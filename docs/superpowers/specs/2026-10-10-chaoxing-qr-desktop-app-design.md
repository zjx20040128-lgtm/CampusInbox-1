# CourseInbox 学习通二维码登录桌面软件设计

## 目标

交付一个面向普通 Windows 用户的桌面软件，而不是要求用户理解本地服务、网址或“检测页”。用户双击软件后，在原生窗口中用学习通 App 扫描官方二维码；登录成功后软件在后台持续读取学习通聊天和课程通知，并把原文及待确认任务保存在 CourseInbox。

第一版的成功标准是：用户无需输入学习通账号密码、无需为登录和监测手动打开浏览器页面、无需安装手机伴侣，即可完成扫码登录、查看同步状态、保持后台监测、暂停或恢复同步以及退出账号。

## 产品形态

- Windows 原生桌面窗口，名称为“CourseInbox 学习通助手”。
- 项目提供可双击运行的 `CourseInbox-Learning-Assistant.exe`，不再把 `start-monitor.cmd` 或 `#sync` 页面作为普通用户的主要入口。
- 桌面程序复用现有 Python 本地服务、独立 Edge/Playwright 登录 worker、SQLite 数据库和 DPAPI 会话加密，不重写已经验证的同步核心。
- 第一版使用 Windows 自带的 .NET Framework WinForms 制作轻量外壳，构建后为单个小型 EXE；不引入 Electron，也不收集用户密码。
- 现有 Web 界面继续保留，作为完整消息、任务、日历和诊断界面，但不再承担首次登录入口的角色。

## 用户流程

### 首次使用

1. 用户双击“CourseInbox 学习通助手”。
2. 软件检查本机 CourseInbox 服务；未运行时在后台启动，已运行时安全复用。
3. 主窗口显示“尚未登录”和“扫码登录学习通”。
4. 用户点击登录后，现有 worker 打开学习通官方登录流程，并从官方 `#quickCode` 元素取得二维码。
5. 软件在原生窗口显示二维码；用户用学习通 App 扫码并在手机上确认。
6. 登录成功后界面自动切换为“正在监测”，无需再次点击。
7. 聊天文字和课程通知按现有轮询策略进入本地收件箱；提取出的任务仍需用户确认后才进入正式待办。

### 再次启动

- 软件读取本机 DPAPI 加密会话并自动恢复监测，不再显示二维码。
- 登录状态失效时明确显示“登录已失效，请重新扫码”，不把网络故障误报为退出登录。
- 一个 Windows 用户同一时间保存一个学习通会话；切换账号需要先退出，再重新扫码。

### 关闭与后台运行

- 点击窗口关闭按钮时最小化到系统托盘，后台监测继续运行。
- 托盘菜单提供“打开主窗口”和“退出软件”。
- 选择“退出软件”才关闭由桌面程序启动的本地服务和同步 worker；若程序只是复用了用户已经启动的服务，则不擅自终止该服务。

## 主窗口

窗口只展示用户需要理解的信息：

- 当前状态：尚未登录、等待扫码、正在连接、正在监测、部分消息待重试、网络重试、同步已暂停、登录已失效。
- 官方登录二维码及“二维码失效时重新获取”。
- 聊天、课程通知、作业/考试来源的本地已保存数量。
- 最近同步时间，以及聊天和课程通知两个来源的独立状态。
- 操作按钮：扫码登录、重新扫码、暂停、恢复、打开消息与任务、退出账号。
- 首次登录出现额外验证时，“打开官方登录窗口”允许用户本人在可见 Edge 窗口完成验证。

界面不再使用“一键检测启动”“检测页”等容易误解的名称。这里的动作统一称为“登录”“同步”或“监测”。

## 架构与边界

### 桌面外壳

新增独立 `desktop-app` 目录保存 WinForms 源码与构建脚本。桌面外壳负责：

- 启动或复用本机 CourseInbox HTTP 服务；
- 通过回环地址取得本机主访问令牌；
- 调用现有登录、状态、二维码、暂停、恢复和退出接口；
- 每三秒刷新状态与分类计数；
- 显示二维码、维护托盘图标并管理自己启动的服务进程；
- 用默认浏览器打开完整的本地消息/任务界面。

桌面外壳不解析学习通网页、不接触 Cookie、不直接写 SQLite，也不复制同步业务逻辑。

### 登录与同步核心

现有 `DesktopSync` 和 `desktop-sync/worker.cjs` 继续负责：

- 启动本应用独立的 Edge 会话；
- 加载官方学习通登录页面并取得官方二维码；
- 接收扫码确认和额外验证结果；
- 通过进程管道传递 Cookie，并使用 Windows 当前用户 DPAPI 加密保存会话；
- 读取聊天文字和课程通知，稳定去重后写入本地收件箱；
- 区分网络重试、局部失败和明确的登录失效。

### 安全约束

- 软件中不提供账号密码输入框，不保存账号或密码。
- 所有登录操作均在学习通官方页面完成，不绕过验证码或额外验证。
- 控制接口继续只允许本机回环地址、正确主令牌和受信来源。
- HTTP 状态、日志和明文文件中不得出现 Cookie。
- “退出账号”删除本机加密会话、二维码和诊断状态，但保留已经接收的原文、任务、草稿和去重记录。

## 监测范围

桌面软件自动监测现有后台 worker 已支持的内容：

- 最近已加载的聊天会话中的文字消息；
- 课程收件通知及可提取的 DOCX、文本 PDF、TXT/MD 说明附件；
- 新内容进入 CourseInbox 后生成有原文依据、需要人工确认的任务草稿。

第一版不承诺同步全部历史，不读取聊天图片、音视频或聊天附件，不代表平台提交作业，也不自动遍历作业/考试中心。作业/考试中心的结构化读取仍保留为“其他同步方式”，直到单独完成真实页面验收。读取官方网页内容可能使平台把相应消息标记为已读，界面和说明中必须明确提示。

## 故障处理

- 服务启动失败：窗口显示可理解的原因和“重新启动”，不静默退出。
- 缺少 Python、Node.js、Playwright 或 Edge：显示缺失项和安装说明。
- 二维码过期：保留登录页并允许重新获取，不要求重启软件。
- 网络中断：保留加密会话并按现有退避策略重试。
- 登录失效：停止使用旧会话并提示重新扫码。
- 单个来源或附件失败：已接收内容继续保留，界面显示“部分消息待重试”。
- 端口被本项目已有服务占用：复用服务；被其他程序占用：提示端口冲突，不结束其他程序。

## 构建与兼容性

- 首期目标为 Windows 10/11 x64。
- 使用系统 .NET Framework WinForms 和现有 Python/Node/Edge 运行环境；构建脚本先检查依赖，再调用系统 C# 编译器生成 EXE。
- EXE、构建说明和普通用户启动说明写入项目文档；旧启动脚本继续保留，避免破坏现有开发和局域网流程。
- 桌面外壳不以管理员权限运行，也不修改系统浏览器配置。

## 验收标准

### 自动化验收

- 桌面程序源码可以在当前 Windows 环境编译为 EXE。
- 服务未运行时能启动并连接，已运行时能复用且不重复启动。
- 隔离测试环境可验证：未登录、等待扫码、登录成功、自动恢复、暂停、重试、失效和退出状态。
- 二维码只在 `waiting_scan` 状态显示；过期或退出后及时清除。
- 退出账号后 `session_saved=false`，原消息、任务和草稿数量不减少。
- 关闭窗口进入托盘；明确选择退出后只终止桌面程序自己启动的进程。
- 原有 Python、Node 和浏览器回归测试继续通过。

### 人工验收

- 双击 EXE 后看到原生软件窗口，而不是带地址栏的普通浏览器页。
- 使用真实学习通 App 扫描官方二维码并确认后，软件显示“正在监测”。
- 真实账号收到一条新的聊天或课程通知后，软件计数增加，并能在本地消息界面看到原文。
- 重启软件后能够复用会话；在学习通使会话失效后能够明确提示重新扫码。

模拟 DOM、自动化测试和匿名官方登录页只能证明软件流程，不能替代最后四项真实账号人工验收。
