# 学习通结构化任务与冲突处理设计

## 目标

在现有学习通聊天和课程通知接入之外，增加作业/考试中心的结构化只读接入；扩展任务字段；把重复消息合并和字段冲突变成显式、可审查的用户流程。

## 边界

- 第一版由浏览器组件在用户打开学习通作业或考试页面时读取可见 DOM，不调用未公开接口，不提交作业，不修改平台数据。
- 后台独立 Edge 的课程通知与聊天流程保持不变。结构化页面解析器与后端接口可供后续后台任务中心扫描复用。
- 所有平台输入先保存为原始消息，再生成草稿；正式任务仍须用户确认。
- 旧任务 JSON、旧 `link` 草稿和现有 SQLite 文件必须继续可读。

## 结构化消息

`kind=task_center` 消息包含稳定平台编号、课程、标题、任务类型、截止时间、提交方式、教师、原始链接、平台状态和字段证据。后端只接受学习通官方 HTTPS 链接，并把平台状态当作证据，不自动写入本地“已提交”。

任务新增字段：`submission_method`、`teacher`、`source_url`、`platform_status`、`confidence`、`field_evidence`。任务类型新增 `presentation`。手动文本仍可通过规则识别常见提交方式和汇报任务。

## MERGE 与 CONFLICT

- 相同课程、班级和明确任务名，无矛盾字段时生成 `merge` 草稿。确认后补齐缺失字段、合并材料并关联来源。
- 明确包含延期、调整等变更词时生成 `update` 草稿。
- 未声明变更但截止时间或提交方式与现有任务不同时生成 `conflict` 草稿。
- 冲突草稿不能普通确认。用户必须选择 `current`（保留当前任务并关联来源）或 `incoming`（采用新消息字段并记录历史）。
- 收件箱增加“冲突处理”标签，普通待确认列表不混入冲突草稿。

## 验证

- Python 单元/API 测试覆盖结构化消息校验、字段持久化、MERGE、CONFLICT 两种决议和旧数据兼容。
- Node DOM fixture 覆盖作业和考试条目提取、官方链接限制和稳定编号。
- 浏览器回归覆盖新字段展示、冲突标签和两种冲突决议。
- 模拟 DOM 通过不等同于真实学习通作业/考试中心验收；需要用户账号页面后续实测。
