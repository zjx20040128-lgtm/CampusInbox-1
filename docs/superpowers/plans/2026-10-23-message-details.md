# 消息详情完善 Implementation Plan

**Goal:** 原文、附件、关联任务和待确认草稿可从一个详情窗口核对，保留人工补充及原始来源。

**Architecture:** 扩展已有只读消息详情接口；继续使用现有原生网页、SQLite、草稿确认流程。沿用用户此前直接实现的授权，在当前工作目录完成，不创建新项目或改写现有未提交工作。

**方案:** 在现有弹窗中集中展示。新增独立页面会重复导航，单纯美化无法解决任务附件遗漏和列表缓存过期，所以采用现有弹窗加只读关联数据。

## 范围与约束

- 原文及发布时间优先；接收时间、网页编号、轨迹折叠。
- 作业/考试和课程通知统一显示已保存附件与读取状态；列表摘要、部分附件不得冒充详情已读全。
- 每次打开/刷新从只读接口获取最新数据；关闭或切换消息后迟到响应不得覆盖当前窗口。
- 确认任务仍在原草稿界面；查看、复制、刷新不写任务或访问平台操作页。
- 链接只允许HTTP(S)，用户文字转义；无新依赖，不改采集器权限。

## 实施

- [x] 后端回归先验证真实来源关联、待确认与已确认区分、无关任务不泄露、只读及隐藏原文保留；再扩展 message_display。
- [x] 详情显示统一附件、真实读取缺口、关联结果；整合补充入口；增加复制原文与只读刷新，防过期响应。
- [x] 隔离浏览器验证任务附件、缓存更新、关联跳转、失败/切换、文本安全、手机布局；相关Python及已有浏览器回归。
- [x] 更新API和验证记录，备份后启用，正式只读复验。
