# Connector 接口与已支持范围

核心入口 `Inbox.ingest(text, source, captured_at, course, scope, event_key, ...)` 保存原文、来源和原发布时间，返回消息与待确认提案。原发布时间不明时要保留未知状态，不把扫描时间替代相对日期依据。平台专用规范化在 `courseinbox/chaoxing.py`，桌面采集在 `desktop-sync/`，两者独立于任务确认逻辑。

当前可用入口：学习通桌面后台采集、浏览器组件、手机通知上传、手动文本/UTF-8文件、截图与本地OCR，以及[QQ OneBot v11本机事件Connector](qq-connector.md)。学习通采集只覆盖已适配可读取入口，详情和媒体缺口持续显示。微信/QQ文本粘贴继续保留；QQ事件Connector需外部消息桥，不包含Windows QQ账号的直接自动读取。

## 新接入应保持的约定

- 原始文字与图片/附件证据保留，来源/发布时间/课程/班级分别记录。Android通知摘要不能伪装成平台完整正文。
- `event_key` 使用稳定平台消息标识；内容、截止或要求变更必须保留为新证据，不能只按标题去重。
- Connector仅负责接收、规范化和可恢复重试；不确认任务、不提交作业、不静默改变本地进度。
- 未读附件、图片、隐藏历史、分页未完成和权限失败应明确记录。登录成功或某次轮询成功不能代表全部来源完整。
- 平台授权和凭据保存在本机，错误/日志不得包含口令、Cookie和私有正文。新增平台需对应真实账号验证，不将通用手动入口称为自动接入。

## 后续实施顺序

QQ事件Connector已实现，下一步用用户选择的消息桥验证实际群事件投递；Windows QQ界面直接读取和微信自动接入仍需单独适配。继续验证相同通知来自学习通和课程群时的任务关联，用户确认后才合并或更新。当前不假定存在官方个人消息API，也不导入、破解或搬运应用的私有凭据。
