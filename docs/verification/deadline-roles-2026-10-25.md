# 开始时间误作截止时间修复

用户指出数字图像处理“作业1：BMP文件的读写”的截止时间为 2026-10-12 10:41，甚至早于通知发布时间 10:45。

## 根因

原课程通知只有“开始时间：2026-10-12 10:41”。旧草稿将其保存为 deadline，关联来源聚合只验证引用日期和年份，没有验证日期语义。在后来确认关联来源时，错误日期被重新补入已确认任务。实时作业只读复核也仅显示“作答开始时间:10-12 10:41”，没有截止字段。

## 修复

- 通用日期提取排除标为开始、发布、接收、采集等角色的日期，保留结束、截止及带日期的提交要求。不以“早于发布时间”作为清空依据，真实历史截止仍保留。
- 关联截止来源重新验证完整原文中的截止语义和实际日期，旧草稿中存在完整年份不再足以证明其为截止时间。
- 旧的待确认课程通知草稿若把非截止日期作为 deadline，在展示和确认时重新校验，防止再次补回错误日期；GET 不修改原始记录。
- 显式数据纠正要求版本一致、原文正向证明日期属于非截止角色，并且所有来源中都没有明确截止依据。只清空已证实的错认值，保留任务状态、要求、原文、附件和完整前后历史。原文缺少截止时间显示“截止待明确”。

## 验证

`tests/test_deadline_roles.py` 先复现开始日期被提取及旧草稿回填，再验证开始/发布/接收/采集角色、真实截止保留、旧引用隔离、原文保护、带版本与审计的纠正以及无证据拒绝纠正。

实时来源复核、完整回归、部署和指定任务纠正记录位于 `artifacts/deadline-roles-20261025/`。

## 已验证结果

- 509 项 Python 测试、48 项桌面测试与 4 项相关日历/截止/延期浏览器检查通过。
- 已将该活动任务的错误截止清空，版本 7→8，并新增“纠正误识别日期”历史；已合并的旧记录保留为历史，不进行二次纠正。
- 其他任务和所有原消息保持原值。纠正前数据库备份位于 `artifacts/deadline-roles-20261025/before-repair.sqlite3`。
- 运行中的页面显示“截止待明确”、任务不再错误显示逾期、不占据日历日期；两个原附件下载入口仍可见。见 `live-ui.json` 与 `task-corrected.png`。
