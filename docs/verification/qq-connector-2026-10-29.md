# QQ Connector 接收端实现与验证

范围：不做人工文本读取试验，直接实现本机OneBot v11事件桥接、白名单、入队、解析、草稿、确认、延期更新和页面配置。没有安装第三方QQ客户端、登录真实QQ、读取真实聊天或改动真实业务库。不是Windows QQ界面自动化采集，也不是腾讯官方个人消息接口。

实现文件：courseinbox/qq_connector.py、HTTP管理接口、server.py的--qq-port、web/qq-connector.js及同步页面挂载。默认关闭；开启后仅在IPv4回环8767监听/events。签名验证兼容OneBot v11 HTTP POST，另支持独立Bearer密钥；密钥由主令牌按独立域派生，不可调用管理API。主令牌不返回给接收器调用方，不记录请求URL/正文/凭据。拒绝浏览器Origin、异常Host、非JSON及超256KB请求。

消息：仅处理白名单群的新入站消息，跳过私聊、本人、心跳。保留接收账号、群号、发件人、平台消息编号、原始消息段、附件描述与实际发布时间。任务范围包含群号，禁止模型把它改到别的群。缺发布时间不向模型传入接收时间，不推测相对日期。图片附件不自动访问URL。原文和媒体描述留存，纯图片不臆造任务。

队列：SQLite入队后才响应成功；最大1000条未完成记录。重复事件幂等，字段顺序变化去重；内容变化保留新证据。失败限次退避、手动重试、重启恢复processing。业务写入后回执落盘前崩溃，重试不重复导入。移除白名单群的未处理事件blocked保留；分析期间暂停也会把事件保留待处理，不继续写入。未投递到本机的消息需要消息桥自行补发，不能保证离线历史完整。

接入复用规则/Qwen、人审草稿、原任务版本、来源与截止更新保护。QQ新任务/已确认任务接入既有桌面和手机/微信提醒事件生成；不向QQ群发消息。页面提供群配置、启停、只读地址、主动复制专用密钥、失败重试与统计；定时刷新不会覆盖未保存输入。QQ来源显示为Connector，与粘贴导入区分。

验证：先新增失败用例，再实施。全量587项Python回归通过（86.250秒）；最后增加JSON字段顺序重排的去重用例并修复规范化哈希后，15项QQ专项通过。专项覆盖签名/Origin、主令牌隔离、非法配置、白名单/本人/私聊、未知发布时间、媒体、两同名群隔离、重启恢复、提交后崩溃幂等、暂停竞态和QQ提醒生成。

Edge临时服务端到端测试通过：页面配置临时端口→签名推送→后台生成草稿→重复推送不重复→人工确认→第二条延期推送→确认更新同一任务；验证原任务确认前不改变，窄屏320/390/1440无溢出、无脚本错误、状态刷新保留编辑。原微信/QQ粘贴、微信推送设置、工作区筛选、补充详情和签到更新浏览器回归均通过。浏览器公共测试启动器新增--qq-port 0，避免测试占用真实接收端口。

尚未验证：真实QQ消息桥的安装/登录、群消息覆盖、QQ附件读取、断网期间消息桥补发、真实手机收到QQ来源的新提醒。未将模拟协议测试当作真实QQ采集成功。上线需用户重启项目并按docs/qq-connector.md配置实际消息桥。
