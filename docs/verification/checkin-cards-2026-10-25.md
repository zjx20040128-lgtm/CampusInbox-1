# 学习通签到卡片识别

- 原因：官方聊天中的签到卡片由 `attachment-item` 的开放 ShadowRoot 渲染；旧解析器只读取 `.bubble-text`，漏掉了该消息。实际卡片结构为 `.attach-item[attachment-type="15"] .attach-info h1/p`，其中 p 是卡片发布时间，不能当作截止时间。
- 修改：仅扩展教学活动中标题含“签到”的卡片；保留原消息 ID、发送人、会话、标题和卡片发布时间。常见签到标题完整保留，分类使用现有“其他”，生成待核对候选，不自动确认或代签。不从卡片发布时间生成截止时间。未给课程名的会话不猜课程。
- 实时采集：观察已加载卡片的开放 ShadowRoot，内容变更可触发原有采集队列；未及时加载的内容仍由后台定时检查兜底。
- 真实会话只读验证：读取到测试会话的 `1612093023015931056`，标题“签到码签到”，发布时间 `2026-10-25T14:24:00+08:00`，结果保存在 `artifacts/checkin-20261025/live-recognition.json`。没有打开签到操作页或发送任何消息。
- 自动验证：新增浏览器测试覆盖真实卡片结构、卡片自身发布时间、ShadowRoot 内容变化触发和非活动附件边界；新增 Python 测试覆盖标题、未知截止时间、未知课程、入库生成候选及重复消息幂等。原 Python 全套 515 项通过，新增第二项入库测试单独通过；原网页解析 12 项及实时采集、真实 worker 模拟测试通过。
- 限制：目前依据聊天中已加载的签到卡片识别；尚未读取签到详情中的结束时间、签到方式参数和个人签到状态，不保证没有聊天卡片的活动已被覆盖。手机提醒到达仍需实际设备验收。
- 已启用：经备份后重启本项目服务，重启恢复采集前五张业务表一致，登录和提醒开关保留。后台实际补收到 3 条签到卡片，包括截图中的签到码签到。更新期间旧后端先将它们生成“签到/作业”候选，已通过现有重新识别接口仅刷新这 3 条尚未人工处理的候选，当前分别显示完整标题、其他分类、未知截止时间和 pending；未确认成任务。结果为 `artifacts/checkin-20261025/live-intake.json`。
