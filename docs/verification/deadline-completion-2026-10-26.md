# 消息截止时间补齐验证

范围：补齐消息记录展示、缺年份的作答区间解析、详情读取失败后的静态正文回退。不增加缺失原因分类界面。

- 消息记录从原文重新核验截止日期，不依赖草稿仍为待确认状态，不直接信任被忽略草稿内的旧日期。多个截止线索不强选第一个。相对日期没有真实发布时间时不推算。
- `task_window.py` 仅解析明确的“作答时间：起点至终点”。采用区间内的明确年份；均缺年份时要求明确发布时间且区间开始距离发布时间不超过31天。仅接受唯一、有效且不超过183天的正向区间，支持12月至次年1月。未使用系统时间、扫描时间、标题中的数字补年份。新采集入库和已有消息展示共用该逻辑；已有草稿可显式重新提取。
- 只读详情读取失败或未解析成功时，若原任务 URL 已通过现有静态作业读取校验，则回退读取同一任务正文。保留禁脚本、禁止提交、身份校验、重定向上限和下一轮重试；考试及未支持入口不扩大访问范围。

测试：Python全套544项通过（96.238秒）；时间UI、任务中心worker、静态正文、作业考试DOM、详情身份和安全导航测试通过。隔离浏览器测试使用临时数据目录与随机端口，不向真实微信发送测试消息。

本地只读核验：AI对进度管理的影响为2026-10-28 23:35；测试作业20261015为2026-10-21 21:16；自然辩证法作业20260915为2026-09-15 17:45，未沿用旧草稿16:25开始时间。

证据目录：`artifacts/deadline-completion-20261026/`。部署使用数据库完整备份和五张业务表哈希比较，保留已忽略决定、任务及原文。真实学习通详情补读的成功率未重新验收；依据不足时继续保留未知日期。
