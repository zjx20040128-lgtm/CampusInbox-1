# 消息发布时间与截止时间展示

日期：2026-10-17。用户要求消息记录关注任务发布时间和截止时间，不关注接收时间。

## 行为

- 消息卡片及详情分别显示“发布时间”“截止时间”；不显示接收时间，不再把作业中心扫描时间冒充发布时间。任务中心卡片用任务名称、要求和平台状态作为摘要，倒计时原始快照仍保存在原文详情。
- 明确采集任务列表/只读详情中的发布时间，保留日期精度与时区。不把任务开始、考试开始、任务名称内日期或剩余时长推算为发布时间/截止时间。
- 服务端保留 captured_at 作为原始观察时间与状态新鲜度依据，另存明确的 published_at。后续补齐发布时间可改善同一消息的元数据，正文与消息编号不变，不新建消息、不改已确认任务。
- 只读 timing 上下文可在唯一来源关系/完整课程班级任务编号下补充已关联发布通知和确认后的截止，分别标注“发布通知”“已确认任务”；来源中的明确截止优先，候选截止标为待核对。没有依据显示“未获取”。
- 消息记录按发布时间倒序，未知排后，每页仍20条。原始领域消息、接收信息及历史继续保留。

## 验证

新增6项 Python 回归，覆盖观察与发布区分、明确时间保存、排序、日期精度、补读防重复、唯一关联与只读原文保留。浏览器验证发布时间提取、考试开始时间排除、明确时区、卡片与详情时间字段、分页与清理、平台状态和既有导入流程。

完整 Python 263项与 Windows 桌面47项通过；7个相关浏览器脚本通过。证据在 `artifacts/message-timing/`，包括 `full-tests.log`、`browser-tests.log` 及对应退出状态；正式部署前数据库及加密会话已备份，具体目录见 `backup.json`。

正式只读检查：“目标检测编程实践”可使用已关联发布通知的 `2026-10-15 22:06`，并显示已确认截止 `2026-10-30 23:59`。这条发布时间标为通知依据，未把正文中的开始时间当作发布时间。“作业20261015”的当前任务中心记录缺少可靠时间关联，保留未知，不按相同标题或倒计时猜测。

本轮不保证学习通所有页面都提供发布时间；只有明确字段或已有可靠来源能补齐。原有消息去重、人工确认和任务历史边界保持。
