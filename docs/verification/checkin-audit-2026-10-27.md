# 签到截止与创建保护补充审计

范围：在临时数据库、临时HTTP服务、模拟学习通DOM和Edge中测试创建绕过、场次关联、重提取、旧任务与提醒。未操作真实签到或修改真实业务数据。

先新增失败测试，复现并修复以下遗漏：

1. 一个活动有有效截止，另一个活动只有已结束状态没有日期时，前端判定歧义但后端只检查有日期的引用，可能创建成功。确认入口现在拒绝统一核验结果中的ambiguous，补充证据时也不从歧义活动填日期。
2. 创建时改任务名称后，旧任务核验依赖标题相等，导致失去过期和提醒保护。现按已经关联的原始签到来源追踪，不依赖可编辑的任务名称。
3. 补充详情生成的新草稿没有external，可能绕过原签到校验。现在通过supplement.original_message_id追溯原始卡片，同时继承原活动身份与结束证据。无详情、已结束、歧义均不能通过补充入口创建。
4. 自定义签到标题不在固定名称列表时，签到类型可能丢失。真实Shadow DOM活动卡片现在携带activity_type=checkin，后端校验并保留；没有类型元数据的短单行“……签到”保守核验。普通“提交签到程序作业”仍按作业处理。空白bubble-text不再遮蔽活动卡片。卡片完整标题在导入和重新提取时保留，不把卡片标题当作截止指令。
5. 刷新草稿会设置manual_review，使唯一活动详情中的截止不再补入，仍可能创建空截止任务。原始、唯一的活动截止现在也可补入重提取草稿，仍由用户确认。
