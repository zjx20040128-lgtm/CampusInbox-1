# 作业倒计时导致重复消息的修复

日期：2026-10-17。

## 根因与范围

实际消息库中，“目标检测编程实践”和“作业20261015”各累积了55条记录。相同课程、班级、任务编号及实质字段没有变化，但 `剩余319小时22分钟` 等文字随扫描变化。原采集器将完整时间文字计入消息编号，后端又按这个编号保存原始消息；原任务去重只能阻止新任务，不能阻止消息列表增长。

## 修复

- 列表及详情版本计算排除独立倒计时，仍保留当时采集到的完整正文。
- 服务端增加索引化的 `messages.capture_key`，由完整平台课程/班级/任务编号、课程/分组、正文中的非倒计时内容及标题、明确截止、要求、附件、教师、提交方式和状态组成。客户端编号不同也不能重复存入同一内容版本。
- 仅忽略独立倒计时片段；“请在剩余2小时内提交”等正文要求变化仍属于新内容。缺少完整编号、其他班级或其他任务不会因标题相同被合并。
- 重放可继续刷新平台检查，不修改确认后的任务版本或进度。相同运输编号被复用且内容变化时，仍保留旧原文并阻止伪造刷新。
- 迁移前自动备份，在事务中新增字段、回填并收起重复记录；中断会同时回滚结构和数据。所有原始行、JSON、来源/提案关联及历史继续保留。消息清理后的版本标记会阻止更换编号的重复扫描再次出现。

## 验证与正式部署

新增7项 Python 回归，覆盖倒计时重放、检查时间刷新、真实内容变化、身份隔离、清理重放、运输编号复用、迁移中断/重试及原文和来源历史保留。另回归作业解析、详情、平台状态、消息分页清理和任务身份的7个浏览器脚本。

最终完整测试：257项 Python、47项 Windows 桌面测试，以及上述7个浏览器脚本全部通过。正式服务健康正常、前端控制台错误为0，原有7项可见任务保持不变。

先在正式库副本上验证：162条可见记录折叠到48条，原始JSON及任务、来源、提案、历史完全一致。随后停止桌面、备份正式库及加密同步目录：

`data/backups/before-message-countdown-20261017-165050/`

正式迁移时原始记录为163条，列表显示48条，115条重复采集从列表中收起；原始记录仍为163条，任务、来源、提案与历史逐行一致，重复可见内容键为0。平台检查时间在迁移后继续推进，倒计时未再新增原始记录。消息记录仍按20条分页。

验证证据位于 `artifacts/message-countdown/`：`rehearsal.json`、`backup.json`、`production-check.json`、`final-tests.log`、`browser-tests.log` 及对应退出状态。最初完整测试遇到正在运行的桌面 EXE 文件锁；停止本项目桌面后重新执行，不将文件锁错误当作领域测试通过。

此修复针对作业/考试中心的重复扫描，不按相同标题吞掉聊天、通知和其他课程来源，也不代表学习通所有入口已完整同步。
