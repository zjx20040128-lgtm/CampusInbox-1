# 规则与 Qwen 分歧核验及独立评测入口

已在本地桌面服务激活，保留人工确认、原文、平台字段和现有任务版本保护。不修改模型权重，不把人工修改后的结果计为自动识别准确率。

## 实现

- Qwen 可以核查已有规则候选，收到任务名、规则截止、提交方式及字段依据；发现问题时按相同任务名提出修正候选，程序负责验证和合并。
- 对截止、提交方式、类型、操作的分歧保存规则值、模型值、原文依据及处理结果，在草稿的“规则 / 模型分歧”中查看。
- 只有原截止引用明确的发布时间/开始时间、引用唯一、模型新截止符合当前任务的确定性语义校验，并且没有平台结构化截止依据时，才修正待确认草稿。平台字段冲突及其他不确定情况保留规则值，人工修改确认。已确认任务不会在分析时被改写。
- 实际 Ollama 诊断发现模型引用了正确日期，却漏传 deadline 参数。工具 schema 现要求该参数；兼容仍漏传的调用，只从原文中的 deadline_evidence 解析并复核日期角色，不读取助手文字回答来补日期。
- 识别评测的“更多选项”新增“新建独立评测集”和评测范围。相同正文去重，同一平台任务或通知的不同版本保留在同一分组；排除已有文件中人工核对过的样本及其同组版本。划分保存后固定，默认只评测留出集，也可选择开发集。
- 留出集历史是否曾被人工或模型接触不能证明，标记历史污染状态 unknown。查看留出错误并据此调参后，需要新的留出样本。分组无法替代真实标准答案。
- 报告逐条比较漏报、误报、截止错误、错误补日期和操作错误，给出当前样本的更好/持平/更差/无法判断。仍展示各项原始指标，组合错误数不是总体准确率，也不是统计显著性检验。
- 补上核对页面的异步加载竞态保护，避免保存时旧响应覆盖刚保存的答案。

## 使用

刷新应用，在“识别评测”顶部选择“独立评测集”，到“核对通知”填写和保存人工答案。列表标明“开发集”或“留出集”。在“更多选项”中选择范围后开始 AI 对比；留出样本尚未核对时不允许启动。建议先核对开发集并改进，再核对留出集作最终比较。

命令行也支持：

```powershell
.\.venv\Scripts\python.exe -B scripts/evaluate-recognition.py --mode compare --models qwen3:4b-instruct --labels data/verification/holdout-20261025.json --split holdout --output artifacts/holdout-comparison.json
```

真实通知原文和标注只留在本机 data/，不要将其提交到公开仓库。附件未读取、相对日期缺少真实发布时间、跨消息复杂指代等输入缺口仍须继续完善；本次不宣称这些问题已全部解决。
