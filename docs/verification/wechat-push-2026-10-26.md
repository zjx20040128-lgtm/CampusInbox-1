# pushplus 微信推送接入验证

实现路径：`courseinbox/wechat_push.py` 独立消费现有学习通提醒事件；由原数据库提交通知立即唤醒，5 秒兜底检查时间阈值，独立于 LAN/SSE/Web Push 的配对、开关和回执。

仅本机主令牌可使用 `/api/wechat-push/status`、`settings`、`test`；公网手机提醒监听器不提供这些接口。Token 固定发送至 HTTPS pushplus 接口的 JSON body，不放 URL，拒绝重定向，8 秒超时，返回大小受限。凭据 DPAPI 加密保存。状态只返回是否已配置及清洗后的结果，不回显提供方错误正文或 Token。

首次开启或恢复基线化已有提醒，保留发布/截止/采集时间语义和原库存初次扫描抑制逻辑。新事件持久化去重，先记录发送中再联网；受理保存流水号但不视为微信送达。明确限流/暂时错误限次退避，失败和模糊结果暂停自动发送，避免盲目重试及刷屏。

测试：Python 全套 **538 项通过**。新增 7 项覆盖凭据加密/不泄露、无 Token 拒绝启用、首次基线、无手机连接仍独立发送、事件幂等、模糊网络结果不重发、限流退避及暂停、固定 HTTPS/JSON/超时、普通聊天原文不外发、主令牌授权及测试 API。浏览器覆盖真实本地设置保存、密码框、清除凭据、未保存设置拦截、区分受理与送达、390px 和无页面错误；测试发送响应模拟，未向真实账号发送。原手机连接页及 Edge 手机网页端到端回归通过，WebKit 仍因未安装跳过。

本机未携带 Token 的接口可达性检查返回 HTTP 200、业务错误 code=999；仅说明网络可以访问 API，不能证明真实 Token、微信绑定、额度或手机通知有效。实际推送需用户在本机配置并点击测试，目前未收到真实 Token，未验收微信送达。

证据：`artifacts/wechat-push-20261026/`；部署前执行完整 SQLite 备份及原五张业务表哈希验证，保留原学习通登录、任务和手机配对。
