## 已复现的问题

使用项目已保存的本机登录会话，只读核对用户截图中的官方课程通知。列表能识别“作业:《测试》作业20261015”，但 GET `/detail` 返回的静态 HTML 中 `.noticeContent` 为空；页面自己的 JavaScript 随后才加载正文。旧手机读取器用 DOMParser 解析静态模板，不执行页面脚本，因此结果为 partial、0 条消息。读取到的网页消息原先也没有调用本机新增任务提醒。

官方详情脚本使用同源 GET `/pc/notice/<uuid>/getNoticeDetail?sendTag=0`，返回的通知 UUID 与列表标识可核对。实际作业原文明确列出：

- 课程名称：测试
- 作业名称：作业20261015
- 开始时间：2026-10-15 19:16
- 结束时间：2026-10-21 21:16

原手机规则不能识别“结束时间”，且标题通用前缀“作业:”会使任务名被截成“作业”。这些是另两个可独立复现的问题，不是对系统通知漏收原因的推测。

## 已实现

- 手机课程通知列表读取静态详情后，缺少正文且无附件时，回退到已核对的同源只读 JSON 接口。对静态标题/时间/发送者先显示、正文稍后加载的模板同样回退，不能把标题显示当成正文读取完成。
- 必须核对 HTTPS 官方域名、详情路由、请求最终 URL、返回成功标识、UUID 及列表标识；拒绝重定向、超限、无权限和身份不匹配的结果。富文本在分离文档中解析，不执行其脚本。纯图片不冒充已读完的空通知；接口明确返回空正文时才允许保存有真实标题的空通知。
- 保留原文和原发布时间。原文没有的截止不补造；将明确“结束时间/结束日期”作为截止，开始时间单独存在时不作为截止。去掉任务类型前缀后保留真正的作业名。
- 在 MobileStore 单线程中比较入库前后任务，成功新建草稿后，每批请求一次任务提醒；点击打开该批最新任务的原消息。重复读取、仅保存普通消息或已有草稿不重复提醒。提醒不确认任务、不代交作业。
- “我的 → 连接诊断”增加系统通知回调数、白名单匹配数、文字字段、通知栏扫描、网页列表/详情/失败数、入库和提醒请求结果。诊断不包含消息正文、登录凭据或配对令牌。

## 手机复核与边界

保留应用和数据，直接覆盖安装。打开“我的 → 课程通知”，点击页面顶部“刷新”，保持页面打开至出现本轮保存数；回到“收件箱 → 全部消息”核对原文，在“任务”核对待确认草稿。确认任务并开启“任务截止提醒”后才安排截止提醒。Android 通知权限或通知频道被关闭/静音时，任务仍可保存，但无法保证弹出提醒。

网页采集仅在该学习通页面打开时运行，不是手机后台定时读取。系统通知后台接收仍依赖 Android 监听回调；“接收正常”只说明当前连接，不能证明某一条通知已经落库。原通知已划掉时，通知栏补收不能恢复它；网页仍保留的通知可由这次修复补收。

没有连接实体手机，尚未验证覆盖安装后的实际补收、新任务通知显示、锁屏接收、OEM 省电影响与未来通知是否再漏收。若再次漏收，在通知仍保留时使用“补收当前通知栏”，并复制“连接诊断”核对回调、匹配、文字与入库阶段，避免再根据单一“接收正常”判断整条链路成功。
