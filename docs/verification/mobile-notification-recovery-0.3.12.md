# Android 0.3.12 通知接收重连

2026-10-13，用户在 iQOO 13（系统版本 16.1.19.11）覆盖安装 0.3.11 后报告：系统“通知使用权”仍开启，但手机页面显示“通知接收仍未连接”；等待一分钟再点“重新连接”依然无效。该截图证明应用尚未收到系统的 `onListenerConnected()`，不证明授权已丢失，也不能单凭截图确定是应用回调顺序还是系统拒绝绑定。

0.3.12 修正两个环节：旧监听实例的迟到断开回调只有在仍是当前实例时才清除连接状态；覆盖安装及开机广播会对已授权但未连接的服务调用 `requestRebind()`，并用不精确系统闹钟在 15 秒、1 分钟、3 分钟、10 分钟后有限次重试。应用打开时也会启动该恢复流程。重连计数和状态在“我的 → 手机提醒”显示，便于区分“已请求系统”与“已收到连接回调”。代码没有改动系统授权或自动开关权限。

验证：通知接收边界测试从 17 增至 20 项，覆盖旧实例断开、新实例仍连、重连限流、无授权不请求、异常和授权读取；重试时序独立测试通过。Android 全套协议与规则测试及 `assembleDebug` 通过。APK 包名保持 `cn.courseinbox.companion`，versionCode 20 / versionName 0.3.12，minSdk 26 / targetSdk 35，签名证书 SHA-256 沿用 `9320aa55a9957826a0bd4df0263f72e03730d35f9bcaf9ad794d562406979177`。内含 `MY_PACKAGE_REPLACED` 与 `BOOT_COMPLETED` 恢复接收器，本机下载路由返回与构建文件相同的字节。

2026-10-14 用户反馈：已在 iQOO 13 上测试 0.3.12，原先的通知重连/重传问题已解决。这是该机型上的用户实测结果；尚未记录多次覆盖升级、开机后长期运行或其他厂商手机的结果。Android 系统仍负责实际绑定通知监听服务，应用不能保证所有设备在覆盖安装后都无需重新授权。

后续反馈修正：用户再次确认每次覆盖更新后系统开关仍开启，但应用显示接收未连接，必须手动关开授权才能恢复。前述成功反馈只证明当次重传成功，不代表跨版本升级已稳定恢复。后续处理见 [0.3.14 绑定重建记录](mobile-notification-binding-reset-0.3.14.md)。
