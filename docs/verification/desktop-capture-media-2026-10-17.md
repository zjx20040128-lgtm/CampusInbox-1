# 电脑端采集、图片/PDF 与任务闭环验证

日期：2026-10-17。对应本轮 PPT 建议中的优先项 1、2、4：采集补读、图片/扫描附件、本地任务闭环验收。模型对比、标注语料、识别率、用户研究和独立安装包不在本轮完成范围。

## 已实现

- 通知详情 DOM 未加载完成时，使用原官方详情页的 `getNoticeDetail` GET 响应补读；核对 uuid 与列表 idCode，不接受串页、登录失效或重定向数据。DOM 慢加载仍保留后续等待与重试。
- 桌面显式启用通知图片采集：只接受已适配的 `p.ananas.chaoxing.com` 官方 PNG/JPG/BMP/WebP 图片；下载禁止重定向和 Cookie 转发，单批8 MiB。原有手机/扩展消费者保持原读取行为，本轮未构建或发布新 APK。
- 通知图片、说明图片与扫描 PDF 使用 Windows 本地 OCR。PDF 最多30页，每次 OCR 最多前10页、循环预算45秒，进程超时90秒；部分输出继续保留缺口，不能刷新完整成功时间。混合 PDF 保留已有可选文字并补充缺字页。
- 相同通知的迟发现图片可补充到原消息；不会重复创建原消息或自动修改已确认任务。已接收通知至少间隔10分钟、每轮最多复查5条，共用原25条/90秒预算；手动重新检查会重读已接收通知。
- 保留 OCR 分行的截止时间和明示提交方式，日期依然要求截止语义证据。
- “学习通同步 → 导出检查报告”只读导出同步覆盖、队列、数据库、重复平台身份、提醒开关和人工核对项目。报告不含正文、凭据或平台链接，`real_acceptance` 固定为 `pending`。

## 自动验证

- Python：250 项通过，项目 `.venv` 未安装可选 pypdf 时也通过。另用已安装 pypdf 的运行时执行5项 PDF 测试通过。
- Windows 桌面：47 项通过，覆盖提醒队列、显示失败保留、ACK 重试、点击目标限制等；这些结果不等同于实际 Windows 通知显示/点击验收。
- 隔离生命周期：官方 JSON 补读 → 草稿 → 提醒队列/回执 → 确认 → 重复来源合并 → 延期 → 冲突显式裁决 → 取消；最终只有1项任务、5个来源，保留历史。报告按钮下载与组件专用令牌拒绝已通过。
- 系统原生 PDF 实测：由仓库示例图片生成的扫描 PDF，在项目实际 Python 环境识别82字，提取“第三次作业”与 `2026-10-12T23:59:00+08:00`。这是合成样例，不是真实教师附件或准确率实验。
- 浏览器回归：测试入口中的18个脚本全部通过，最终退出状态0。包含新增图片解析、官方补读、定期/手动复查、原有手机读取兼容性、任务身份与平台状态、OCR、提醒/任务页面、课程通知和后台会话恢复；最终结果见 `artifacts/desktop-capture-media/browser-regression.log`。

复核发现分行 OCR 的截止信息曾被过滤；已增加回归并修复。独立复核会话因用量限制未完成全量审查，后续由本轮逐项自查和自动回归覆盖，不将其记录为独立审查通过。
