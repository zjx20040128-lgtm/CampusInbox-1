# 从通知正文识别完整任务

## 用户流程

导入通知 → 只粘贴消息正文 → 提取任务草稿 → 核对课程、名称、日期、类型、提交方式和任务要求 → 确认。

正文是默认唯一必填项。来源、课程、班级、真实发布时间、提取方式折叠到“补充信息（可选）”，截图和文件保留为单独的可选入口。已配置模型时默认使用规则加模型辅助；仍可展开选项指定规则模式。

## 接口与约束

新增经主访问令牌保护的`POST /api/import/text`。最小请求为`{"text":"完整通知正文"}`；支持可选source/course/scope/published_at/mode，mode为default/rules/agent。

- 从原文显式“发布时间：…”提取真实时间，从“班级/分组/课程群：…”提取范围；课程、类型、要求等由规则和模型从正文识别。
- 不预填导入时刻为发布时间。没有真实发布时间时，模型仍可识别任务和非时间字段，明确包含完整年份的日期也可提取。
- 内部中性日期仅供解析，向模型明确声明publication_known=false。最终日期继续通过未知发布时间和原文引用校验，禁止用当前日期推算“明天、下周”或补年份。
- 中文完整年份在无发布时间时可用；缺年份的实验安排不会泄露成内部占位年份2000。
- 日期角色规则增加“某日前将/把材料投递、发送、提交…”的有限肯定指令；否定指令不产生截止。
- 留存原文、来源、发布时间是否已知和调用状态；重复文本与相同上下文不重复调用模型、创建消息。
- 任务确认前只保存待确认草稿，不改写已有确认任务；原文缺失的字段保持空白，不保证无依据的所谓“完整”。

## 验证

- 8项文本导入测试覆盖最小正文完整字段、正文发布时间/班级、无发布时间时模型补任务、无关消息、重复请求、中文完整年份、占位日期排除、投递邮件截止与否定表达。
- 文本导入浏览器测试通过：只填正文、可选项折叠、鉴权、全部字段填充、无发布时间时模型兜底、确认前任务库为空、窄屏。
- 微信/QQ文本导入、课程通知重新提取、手动截止日期编辑、任务筛选浏览器回归通过。旧浏览器测试改为展开可选入口，并按实际要求内容校验，不要求无意义的空行。
- 真实DeepSeek测试只提供一段虚构正文，无额外信息框：成功提取软件工程/实验一/实验/2026-11-03 20:30/投递到课程邮箱/Python与运行截图要求，实际2次请求。测试用临时数据库，未写入真实消息或确认任务。证据：`artifacts/text-import-deepseek-live-20261029.json`。
- 最终Python回归日志：`artifacts/text-import-20261029-final-tests.log`。

## 生效

需要完整退出桌面托盘并重新运行start-desktop.cmd，加载新接口后刷新网页。旧服务未加载新接口时，导入框提示重启，不会丢弃用户已粘贴的文本。
