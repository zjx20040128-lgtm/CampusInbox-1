# 安卓网页后台推送

用户要求手机不打开网页也能收到电脑提醒，明确选择安卓，并在 HTTPS 隧道失败后选择“没有域名，稍后换网络重试”。

实现：

- `courseinbox/web_push.py`：每设备浏览器订阅、P-256/VAPID、AES128GCM 加密发送；当前用户 DPAPI 加密持久化服务器私钥。数据库提交唤醒发送线程，无需手机页面建立 SSE 或轮询；每 15 秒兜底检查时间阈值。发送网络请求有超时、禁止重定向、允许的推送服务主机白名单及公钥合法性校验。
- 配对后的独立设备令牌授权订阅、取消和公钥请求，不暴露主管理令牌。撤销设备同步移除订阅，404/410 移除过期订阅；网络失败退避重试。服务端接受推送和手机实际读取回执分别记录，不将供应商返回 2xx 当成手机已送达。
- 手机提醒页面增加“开启后台提醒”，只在用户点击后请求通知授权。Service Worker 在页面关闭时显示系统通知，点击通知打开提醒页面。停止接收、关闭后台提醒和断开配对可取消订阅。原局域网 SSE 保留。
- HTTPS 代理仅接受配置的明确域名、从本机转发的请求，继续拒绝主管理 API 和跨站来源。根目录提供 `启动手机后台提醒.cmd`，对应 PowerShell 脚本下载并校验 Cloudflare 官方二进制 SHA256，创建仅转发提醒端口的临时 HTTPS 入口；隧道及 HTTPS 健康检查成功才公布地址。
- Quick Tunnel 不支持 SSE，因此该临时 HTTPS 入口的前台补收采用有限请求；真正的后台通知由 Web Push 服务发送，与手机页面是否打开无关。长期使用需要稳定 HTTPS 域名。

验证：

- 完整 Python 回归 **531 项通过**；新增测试覆盖授权、端点/密钥验证、加密及 VAPID 签名、请求超时/禁止重定向、提交唤醒无手机请求的后台发送、重复发送抑制、失效订阅清理、撤销和无虚假手机回执。
- 真实 Edge 浏览器实际注册 Service Worker、授权通知并保存隔离订阅；关闭页面后，使用 Chromium DevTools 注入本地 push 事件，系统通知可通过 ServiceWorkerRegistration.getNotifications 读取。订阅服务地址在此测试中模拟，**不证明真实 FCM/安卓锁屏链路**。
- 原 Edge 手机网页配对、前台 SSE、回执、停止/恢复、跨标签页/重新配对、撤销和窄屏回归通过；电脑手机连接页测试通过。WebKit 浏览器未安装，未宣称其通过。
- 更新前完整 SQLite 备份及原业务表哈希保全，学习通会话和手机配对保留。

后续定位与修复：最新隧道预检明确显示 UDP/QUIC pass、TCP/HTTP2 fail，之前固定 HTTP/2 是本次无法连接的配置原因。独立 QUIC 进程注册成功，启动器改为 auto 协议。原 PowerShell HTTPS 检查与项目代理环境不同，改为调用 `scripts/check-phone-https.py`，同时校验提醒服务身份。实际外网健康接口和 sw.js 返回 200、主管理 API 返回 404、未授权推送公钥返回 401；真实 Edge 验证 isSecureContext=true。成功进程由启动器记录并复用，未修改系统代理或 DNS。临时入口已可用，但当前仍是 **0 个 Web Push 订阅，安卓实际锁屏送达待验收**。证据见 quic-health.json、startup-quic-reuse.log。
