# 学习通原附件发现与展示

2026-10-25。用户报告数字图像处理两份作业缺少 BMP 附件。

## 原因和改动

- 已保存的两个作业正文包含文件名，但 attachments 为空、media_pending_count=2。不是 BMP 后缀不受 OCR 支持：已有 BMP OCR 分支。
- 实际作业使用 `.attachNew span[data][name]` 和 `iframe.attach-iframe` 的编码 objectid 元数据，原采集器只接受显式下载链接。
- 对已经核对任务身份的可见说明区域补充两种元数据解析；仅接受 32 位十六进制对象 ID 与固定官方下载域。下载限制、隐藏内容、个人答案、非法元数据仍不会生成文件链接。
- 原文件发现不限制后缀，BMP/RAW、ZIP/RAR/7Z、代码、表格、演示稿、其他后缀均可保留链接。这不代表新增相应格式的文字解析器。
- 任务详情直接汇总已关联来源中的附件，按 URL 去重；原文件与文字读取状态区分。
- 同一任务观察补收原附件时，可增加附件清单；保留旧文件及已提取文字，禁止替换/移除旧附件，不修改已确认任务、日期和状态。

## 验证

- 新回归先复现两种 BMP 元数据漏收、任务详情无附件，以及相同消息不能补收新发现附件，再修复。
- `scripts/test-attachment-formats.cjs`：后缀无关发现、两种 BMP 结构、去重、非法对象、下载限制、个人答案隔离及二进制原文件语义。
- `scripts/test-task-attachments-ui.cjs`：确认后任务直接显示 BMP/RAW/ZIP/CPP 链接及 390px 布局。
- `tests/test_attachment_discovery.py`：原消息原位补充附件、保护确认任务及已有文字、拒绝替换/移除。
- 真实账号只读静态作业验证：作业1 `lena.bmp`、`text.bmp`；作业2 `image1.bmp`、`image_color.bmp`。四个文件全部解析到官方链接；没有执行作答页面脚本、提交表单或修改平台任务。

完整运行结果与部署记录在 `artifacts/attachment-formats-20261025/`。原文件链接的后续可用性受平台权限及网络影响；复杂附件内容理解仍按已有能力处理。
