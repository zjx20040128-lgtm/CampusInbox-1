# 任务说明与附件读取（2026-10-22）

本轮沿用现有电脑端实现。初始离线核对的6项任务全部来自 `/mooc-ans/mooc2/work/task`，带 answerId，没有已保存的说明正文。此类页面继续不由后台自动打开，也不根据URL猜测其他入口。

## 实现

- 作业列表如明确提供同任务的只读说明链接，自动识别后读取。课程、班级和作业编号均须一致；原操作链接仍作为来源，说明链接单独保存。优先使用列表条目本身的任务URL，避免附件或其他任务链接替换任务身份。
- 说明页仅允许同一任务的只读导航；禁用页面脚本，阻断全部非导航资源及写请求。重定向到操作页、错误身份、标题空壳均不能当成正文读取成功。页面依赖脚本加载而无法读取时继续保留待核对状态。
- 任务说明附件接入现有8MB下载与正文提取链路。名称、链接、正文及部分/失败状态保留；原任务要求与附件正文一同进入待确认草稿，不自动确认任务。非支持附件与超过20个附件的部分继续计入缺口。
- 同一任务附件首次失败后成功，按相同正文、身份、附件清单做单调升级，保持原消息与来源。已有部分正文与新正文不兼容时保留旧文并提示核对。
- 清单根据实际入库内容更新；已提取附件列表重放不降级，新媒体缺口不会被旧成功回执覆盖。已忽略/归档/清除记录不因附件补读复活。清除回执使用原消息墓碑，不能把未入库的合成回执当作新正文。
- 浏览器组件更新至0.3.2；已有扩展需要重新加载更新后的组件目录。电脑端后台直接复用共享解析器。

## 实际平台边界

以上合成测试不等于6项实际作业已读取成功。实际自动读取需要平台当前列表提供已支持、同身份的只读说明链接，并且说明有可提取的服务端正文。没有此类入口、需要脚本动态加载、媒体无法提取或涉及作答/提交时，继续由用户打开原任务核对。

本轮没有教师发布、答题、提交作业、自动确认真实任务，也不把规则回归或消息回执当作Windows通知/休眠/真机验收。
