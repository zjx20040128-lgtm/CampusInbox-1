2026-10-15～16。用户在 iQOO 13（vivo V2408A，Android 16 / API 36）安装 0.3.16 后，收件箱仍没有新作业。此次没有连接实体手机；以下区分用户诊断、代码回归、真实网页验证和手机待验收项。

后续 2026-10-16 用户发现历史已截止任务也进入待确认。下文“9 条草稿”证明读取与入库链路，不代表这些草稿都仍有效。已在 [0.3.18](mobile-historical-tasks-0.3.18.md) 增加时效过滤及旧草稿修复；同一批原文重放后保留 3 条待确认，原旧档 6 条历史草稿被忽略，原文保留。

## 诊断与可复现原因

用户复制的诊断中，通知使用权已开启、监听服务已收到系统连接回调；最后一条匹配通知是分组摘要，当前通知栏没有学习通通知。网页状态是 `authenticated`，列表、详情、保存和新增任务均为 0。

这说明该次网页结果只确认了登录，没有提供课程通知读取结果；不能据此倒推所有历史读取均未发生，也不能证明某条系统通知已成功保存。分组摘要不能补出隐藏的作业正文。

入口代码可独立复现两个断点：收件箱主按钮打开门户，门户确认登录后没有继续原请求来源；首页“刷新”只重读本机存档。已登录、服务连接正常与课程通知实际入库是三个不同状态。

本次真实通知为“作业:《人工智能与深度学习》目标检测编程实践”，发布时间为北京时间 2026-10-15 22:06。原文明确写明开始时间 2026-10-15 22:04，结束时间 2026-10-30 23:59。

## 实现

- 收件箱主按钮为“登录并同步学习通 / 同步学习通”。收件箱和全部消息的“刷新”直接请求官方课程通知来源；已知门户给出登录证据后，继续原请求来源，限制为官方可信路由并防止重定向循环。账号中的手动门户和聊天入口保留。
- 课程通知每批最多 5 条，按剩余条数读取末批；一轮检查当前列表最多 100 条，保存后返回收件箱。检查、保存、新增任务、未读及保存失败数量各自展示；部分失败也明确保留结果。门户不再覆盖上次实际读取记录为“保存 0 条”。
- 每页控制器独立；读取请求有递增标识并只能消费一次。导航、暂停与恢复后的旧回调不能重置新批次状态。已开始的写盘完成后保留结果；写盘、诊断和提醒处理结束才释放批次状态。
- 新草稿保存后请求本机提醒。首页发起的整轮同步最多请求一次，后续批次不再次发通知；用户划掉后也不会因同轮后续批次重新弹出。重复来源读取不重复建草稿。手动来源页面保留按批次处理。
- 连接诊断增加当前官方页面、最近一次课程通知检查时间和结果；首页显示真实同步结果。诊断不输出消息正文、登录凭据或配对令牌。

Android 的 `setOnlyAlertOnce` 只约束仍在显示的通知更新，所以整轮去重另外由读取控制器限制请求次数，见 [Android 官方说明](https://developer.android.com/reference/android/app/Notification.Builder#setOnlyAlertOnce(boolean))。

## 手机验收与边界

保留应用和数据直接覆盖安装。在收件箱点“同步学习通”或“刷新”，如需登录则完成官方登录，保持页面打开至返回收件箱。核对首页的本轮结果，再到全部消息查看作业原文，到任务查看待确认草稿。真实手机已有数据可能与隔离存档不同，新增数量不一定为 9；重复同步应不产生重复草稿。

截止提醒仍需先确认任务并开启“任务截止提醒”。新增任务提醒需 Android 通知权限和频道允许显示。本轮没有新增常驻后台网页服务，系统通知后台漏收、锁屏/OEM 省电影响、实体手机覆盖安装后读取与提醒显示仍未验收。“接收正常”只证明当前监听连接，不能替代完整消息链路验证。
