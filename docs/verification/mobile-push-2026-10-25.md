# 手机网页提醒长连接推送

用户要求由手机主动轮询改为电脑推送。范围为 8766 手机网页提醒；Android 伴侣及桌面提醒接口保持兼容。

## 实现

- 新增带独立设备令牌认证的 `/v1/stream` SSE 流，使用 Fetch 流读取，使令牌留在 Authorization 请求头。
- Inbox 数据写入成功提交后通知订阅者，唤醒长连接并立即发送新提醒；回滚事务不通知。手机回执/在线状态写入不触发全局唤醒，避免自激循环。
- 空闲连接发送心跳并检查时间驱动提醒。客户端不定时请求 `/v1/alerts`，仅断线后退避重连；旧接口保留供兼容调用。
- 原有本地持久化、重复事件去重、独立回执、重连补收、停止/重新配对及跨标签页代际检查继续生效。
- 页面进入后台会关闭连接，返回后恢复并补收；停止接收立即中止连接。电脑撤销设备时主动结束其授权并通知网页。
- 本方案仍要求手机网页保持打开；不能宣称关闭网页、后台冻结或锁屏后仍有系统级推送。

## 验证

- `tests/test_mobile_push.py`：认证、提交后即时推送、回执、撤销、成功提交与回滚通知边界。
- `scripts/test-phone-reminders.cjs`：真实隔离服务配对/推送/回执；确认浏览器不调用 alerts 轮询接口，新消息复用已有流连接；重载去重、停止/恢复、跨标签页重新配对、旧响应隔离、撤销、320/390px 和文本安全。
- Edge 验证通过，环境没有 WebKit 浏览器可执行文件，未宣称 Safari/真机验收。
- 完整回归和部署记录在 `artifacts/mobile-push-20261025/`；真实手机刷新后的接收仍需用户实际验证。
