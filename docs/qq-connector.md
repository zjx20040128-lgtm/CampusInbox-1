# QQ Connector（OneBot v11 本机事件桥）

此 Connector 接收同一电脑上 QQ 消息桥推送的群消息，自动保存来源并生成待确认草稿。它不是腾讯官方 QQ API，也不直接登录或读取 Windows QQ 客户端；需要用户另行选择并配置可用的 OneBot v11 消息桥。没有配套消息桥时，只有接收入口，不会自动得到 QQ 消息。

## 启用

1. 从托盘彻底退出 CampusInbox，重新运行 `start-desktop.cmd`，加载新后端。
2. 打开“学习通同步”页面，下方新增“QQ 消息接入”。
3. 每行填写 `群号 | 群名 | 课程`，课程可以省略，例如 `123456789 | 软件工程课程群 | 软件工程`。
4. 勾选“开启接收”并保存。默认只在 `127.0.0.1:8767` 监听；占用时页面报错，不开放到公网。可使用 `python server.py --qq-port 其他端口` 指定端口。
5. 展开“消息桥配置”，将页面显示的 HTTP 事件上报地址和复制的接入密钥填入消息桥的 HTTP POST URL / secret。消息桥需按 OneBot v11 对原始请求体发送 `X-Signature: sha1=HMAC-SHA1(secret, body)`；也支持 `Authorization: Bearer <独立接入密钥>`。各消息桥的配置界面名称可能不同。

接收服务开启只表示本机入口可用；最近消息和处理计数才说明是否有实际数据到达，不代表群历史完整。不要把 CampusInbox 主访问令牌交给消息桥。OneBot 接入密钥只能向 QQ 接收入口提交事件，不能管理任务或读取管理 API。

## 处理流程

白名单课程群事件 → 签名验证 → SQLite持久化队列 → 规则优先、按项目配置使用Qwen辅助 → 收件箱草稿 → 用户确认 → 创建/更新原任务。

保存接收账号、群号、发件人、平台消息编号、原始消息段、实际发布时间和媒体描述。班级范围包含群号，避免同名群串任务。发布时间缺失时保持未知，不用收到消息的时间推算“明天”或年份。私聊、本人发送、非白名单群和非消息事件不会生成任务。

相同事件重复推送幂等，JSON对象字段顺序变化也不会重复。相同消息编号但内容改变时保留新证据，不覆盖旧消息。入队成功后返回200；队列满、签名失败或暂停时不会报告接收成功。消息桥需要对未成功投递自行补发，Connector不能补抓未送达的历史消息。

已入队事件失败自动限次重试，错误不含私有正文或凭据，原事件保留；页面可重试失败消息。重启恢复未完成队列；业务写入后回执落盘前崩溃，重试仍不会重复创建来源。暂停后不再继续导入正在分析的事件；重新开启后可继续处理。

图片、文件、转发卡片等仅保留消息段和来源信息，不自动访问附件URL，不承诺已经提取内容。纯图片事件不会凭空生成任务。允许群被移除时，队列中该群的未处理事件保留为blocked，不会继续导入。

QQ新任务草稿和已确认任务接入现有桌面、手机/微信提醒生成流程；不会向QQ群自动发言。没有真实QQ账号和消息桥验收之前，不将协议模拟测试称为真实群采集成功。

## 本机管理 API

以下接口均要求 CampusInbox 主访问令牌：

- `GET /api/qq-connector/status`：配置、监听状态、队列统计，不返回密钥。
- `GET /api/qq-connector/credential`：获取独立接入密钥，仅在主动复制时调用。
- `POST /api/qq-connector/settings`：`{"enabled":true,"groups":[{"id":"123456789","name":"课程群","course":"软件工程"}]}`。
- `POST /api/qq-connector/retry`：空JSON对象，重试已失败事件。

独立接收器只支持 `POST /events`，仅监听IPv4回环、校验Host、拒绝浏览器Origin，不支持跨域和URL令牌；JSON请求体最多256KB，未处理队列最多1000条。默认关闭。测试用 `--qq-port 0` 分配临时端口，使用临时数据库，不写真实消息。

协议依据：[OneBot v11 群消息事件](https://github.com/botuniverse/onebot-11/blob/master/event/message.md)、[HTTP POST 与签名](https://github.com/botuniverse/onebot-11/blob/master/communication/http-post.md)。
